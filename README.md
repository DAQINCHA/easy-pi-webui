# easy-pi-webui

给 [pi](https://pi.dev) 做的一个网页界面，面向不写代码、不看代码的小白 vibecoder：不用记命令、不用读代码，打开网页就能给 pi 派活、看进度、管理会话。底层用 pi 自己的 RPC 模式跑真实的 pi 会话。

零 npm 依赖：服务端只用 Node 内置模块，前端是原生 HTML/CSS/JS，没有构建步骤。

## 启动

前提：Node.js 22.19 或更新，并且已经装好、登录过 pi（终端里 `pi --version` 有输出）。

```bash
cd node-server/easy-pi-webui
npm start
```

自动化测试（不占用 30142，不读真实会话、不发模型请求）：

```bash
npm test
npm run check
```

然后打开 <http://127.0.0.1:30142>。macOS 下也可以直接双击 `启动 easy-pi-webui.command`（它会起服务并帮你打开网页）。

工作目录按下面的优先级决定，**每台电脑各自记住自己的选择**，配置写在 `~/.config/easy-pi-webui/settings.json`（不在 iCloud、不碰 `~/.pi`）：

1. 命令行 `--workspace /path`
2. 环境变量 `PI_WORKSPACE`
3. 这台电脑上次保存的选择
4. 都没有 → **首次使用**：网页会弹出「选择工作目录」，选好才允许发消息；此时不会启动任何 pi 子进程、不会发模型请求、不会恢复或新建会话。

显式参数 / 环境变量给的路径无效时会明确报错并进入「未选择」状态，不会悄悄换成别的目录；保存的路径失效、配置文件读不出来也一样。选择保存在本机，命令行 / 环境变量的覆盖只在当次生效，不改写配置文件。

启动后在左下角点「工作目录」也能随时切换，不重启服务就能换项目；页面主动切换会保存为新默认。系统目录选择框只在 macOS 可用，其他系统可以直接在弹窗里输入绝对路径。最近使用的 8 个目录记在浏览器本地，只作为快捷入口，不参与启动默认值。

## 能做什么

- 会话侧栏：按「今天 / 昨天 / 7 天内 / 更早」分组，能开多个会话，切走的会话在后台继续跑
- 历史搜索：侧栏搜索框会在当前工作区的会话标题和可见对话正文里查找（默认不搜工具原始输出、隐藏的思考过程和附件二进制）。大小写、多余空白不影响中文或英文匹配，输入的符号按原样查找、不会当成正则。结果带短摘要和「标题匹配 / 对话匹配」提示，归档会话会标明「已归档」，点一下即可打开。默认侧栏只列出最近 80 个会话，但正文搜索会扫当前工作区里更多会话文件，并如实显示已查看数量和是否截断。清空搜索会回到原来的列表和置顶状态。搜索本身不会启动 pi 或请求模型
- 会话导出：在会话右侧「…」菜单里可导出 Markdown 或可离线打开的网页。导出的是当前会话的活动分支（重新生成后被放弃的内容不会拼进来），默认只有你和助手的可见正文、标题和时间，不含隐藏思考、工具原始输出或密钥。图片和本地文件路径会标明离线无法打开，也不会自动打包私密附件。导出不会请求模型
- 工作区切换：左下角目录卡片点「打开工作区」在 Finder 里选目录，或点最近目录；记住最近 8 个（悬停可删除记录），不重启服务就能换项目
- 重新生成 / 另开分支：助手回复下有「重新生成」和「另开分支」。用户发言下有「复制」和「编辑」，没有「重新生成」或「另开分支」。「重新生成」留在同一个会话里，原来的回答还在（作为旧分支保留），按原来的请求再生成一遍。点之前会提示「重新生成会重新执行任务；已修改文件不会自动回滚」。「另开分支」会新建一个独立会话（不是在当前会话里分叉），原来的对话不动；输入框里是原来的请求（含图片），由你改完再发，不会自动请求模型。新会话在列表里会显示「原标题 · 另一分支」。正在回复或等待确认时按钮会先停用，也不会中断当前任务。
- 消息编辑：用户消息下有「复制」和「编辑」，会把完整原文（含图片）放回输入框；取消或离开都不会改对话。只有你真正发送时，才会从这条请求之前继续，原来的回答还在。
- 任务状态：对话底部用一句话说明正在做什么（思考、写回复、读取或修改文件、运行命令）、是否在等你确认、是否已完成 / 失败 / 已停止。连接断开会单独提示，不会当成任务失败。结束时只根据真实事件写短摘要（例如实际改了几个文件），不会写成「已完成你所有要求」。工具和思考的展开细节仍在原来的过程条里
- 本轮改动摘要：每轮结束在回答下方居中出现一个「N 个文件已更改」胶囊，点开列出每个文件和所在目录；点文件名可预览或下载。只讲文件改动，不显示增删行数、不统计命令数。只认 `edit` / `write` 的路径，用 `bash` 间接写文件统计不到，那一轮没记录到文件就不显示胶囊。回复里的本地文件链接（如 `[报告](./out/report.md)`）同样可点开
- 完成通知：顶栏铃铛图标开关「完成时通知」（默认关），页面不在前台且本轮成功结束时弹系统通知；主动停止、任务失败、断线回放不弹
- 完成音效：本轮成功结束时响两声短促的提示音（「叮—咚」，G5→D6），没有开关。声音用 Web Audio 现场合成，不加载音频文件；主动停止、任务失败、断线回放不响
- 可安装（PWA）：支持的浏览器可以把界面「安装到桌面 / 手机主屏」，用独立窗口打开；断网时至少还能打开外壳（界面 + 样式 + 脚本），但聊天、会话、模型都必须联网才能用
- 自动命名：第一次对话结束后，让模型起一个短标题并存进会话（`PI_AUTO_TITLE=0` 可关闭）
- 会话置顶：活动会话悬停时，归档图标左边多一个图钉图标，点一下即置顶（再点取消）；置顶的会话收进侧栏顶部独立于时间分组的「已置顶」分组，归档会话会自动取消置顶
- 会话归档：活动会话悬停点右侧的归档图标即可归档；归档的会话收进侧栏底部「已归档」分组，点「…」可以取消归档或删除会话
- 流式回复：文字边生成边显示，代码块有语法高亮和复制按钮
- 思考过程：折叠显示，可展开
- 工具调用：命令、文件读取、编辑差异（红绿 diff）、写入内容都以卡片展示，可折叠，带耗时和成功/失败状态
- 模型与思考深度切换、上下文占用百分比、token 与费用统计
- 斜杠命令：`/skill:xxx`、prompt 模板、扩展命令，输入 `/` 就有候选
- 图片与文件：粘贴、拖入或点回形针按钮添加。图片仍按原来的方式随消息发给 pi；普通文件会先保存到当前工作目录下的 `.easy-pi-webui/uploads/`（唯一文件名，不会覆盖），发送时把保存路径写进消息，让 pi 用工具去读。一次最多 6 个附件，图片上限 8MB，其他文件上限 20MB。文本 / Markdown / 常见代码和 JSON 等可在界面里只读预览（已转义）；PDF / Office 等不能在本界面解析，会明确提示需 pi 工具或下载后用本机应用打开。HTML / SVG 不会在页面里运行
- 压缩上下文、重命名会话、停止当前任务（Esc）
- 深色 / 浅色 / 跟随系统三种外观，窄屏自动变成抽屉式侧栏

## 它是怎么跑起来的

浏览器 ←SSE← Node 服务 ←JSONL/stdin+stdout→ `pi --mode rpc` 子进程

- 每个会话对应一个 pi 子进程，会话文件仍然写在 `~/.pi/agent/sessions/`，和命令行里的 pi 完全共用
- 服务端把 pi 的事件原样转发给浏览器，浏览器负责拼出流式消息和工具卡片
- 15 分钟无活动、没有连接、也不在跑任务的子进程会被回收

用的是 pi 官方文档里的 [RPC 模式](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)，不是进程内 SDK——这样不用装 `@earendil-works/*` 依赖，也不会和已安装的 pi 版本打架。两者用的是同一套会话、模型和工具。

## 配置

| 环境变量 | 作用 | 默认 |
| --- | --- | --- |
| `PI_WORKSPACE` | pi 的工作目录（会话也按它分组）；仅当次生效，不改写本机配置 | 本机保存 / 首次选择 |
| `PORT` / `PI_WEBUI_PORT` | 监听端口 | `30142` |
| `HOST` | 监听地址 | `127.0.0.1` |
| `PI_BIN` | pi 可执行文件路径 | `pi` |
| `PI_SESSION_DIR` | pi 会话根目录 | `~/.pi/agent/sessions` |
| `PI_AUTO_TITLE` | 设为 `0` 关闭首次对话后的自动命名 | 开启 |
| `PI_TITLE_MODEL` | 生成标题用的模型（对应 `pi --model`） | pi 默认模型 |

也可以用命令行参数：`node server.js --workspace /path --port 30142 --host 127.0.0.1`。

## 停止与退出

- 前台 `npm start` / `node server.js`：按 `Ctrl + C`（SIGINT），或直接发 `SIGTERM` / `SIGHUP`，都会走同一套清理。
- 双击 `启动 easy-pi-webui.command`：关掉那个终端窗口、按 `Ctrl + C`、或终端断开导致的 HUP 都会触发清理；脚本只向自己记录的那个服务进程转发信号，不会按端口杀进程、不会误杀别的 pi 或 node。
- 退出时会停止接收新请求、关掉 SSE、回收所有 pi 子进程和自动命名子进程（先 TERM，必要时 KILL，有超时兜底），确认退出后才结束。重复发信号不会重复清理。
- **不会**因为关闭标签页、刷新页面就杀掉正在跑的任务；断页继续和 15 分钟闲置回收保持原样。
- 限制：`SIGKILL`、系统崩溃、断电无法捕获；没有设计进程组，因此不保证 pi 自己派生的任意孙进程全部被回收；也不会去碰你独立开的命令行 pi。

## 注意

- 默认只监听本机。改成 `0.0.0.0` 等于把「能执行命令的 agent」暴露到局域网，而且这个界面没有登录功能。
- 侧栏只列当前工作目录的会话；用左下角的目录卡片切换，切走的目录里正在跑的会话会留在后台。
- 系统目录选择框目前只在 macOS 可用；Windows / Linux 可以在选目录弹窗里直接输入路径。
- 保存配置文件失败时会明确提示「目录已切换但没记住」，旧配置不会被覆盖或损坏；重启后需要重新选择。
- 还没做：项目文件浏览、Git 面板、导出 HTML。不会根据命令输出猜测「已生成某个文件」；只有确实存在、且位于当前工作目录内的文件才能预览或下载。切换工作区后，按新目录鉴权，旧目录里的路径打不开。

## PWA / 离线外壳

Service Worker 只在**安全上下文**里工作：`http://127.0.0.1:30142`、`http://localhost:30142` 或 HTTPS 都算；用局域网 IP 走普通 HTTP（例如 `http://192.168.1.10:30142`）不行，浏览器会直接拒绝注册，页面本身照常能用，只是不能安装、也没有离线外壳。

- **安装**：用 Chrome / Edge 打开页面后，点地址栏右侧的安装图标（页面内不再单独提供安装入口）。iPhone / iPad 用 Safari 的「分享 → 添加到主屏幕」。
- **断网**：外壳用 network-first 缓存，断网刷新还能看到界面；但 `/api/*` 一律不缓存、不伪造，所以这时会话列表和发消息都会报「后端未连接」之类的错误，这是正常的。
- **更新**：静态资源同样是 network-first，改完前端刷新就是新代码，不会卡在旧缓存；SW 自己 `skipWaiting()` + `clientsClaim()`，新版本不用关光所有标签页。
- Service Worker 注册失败（比如浏览器禁用、非安全上下文）不影响页面其他功能，只是不能安装、断网打不开、通知回退到普通 `new Notification`。

### 图标

安装清单已接入这些路径（请直接替换文件，不必再改路径）：

- `public/icons/icon-192.png`：常规 192×192（`purpose: any`）
- `public/icons/icon-512.png`：常规 512×512（`purpose: any`）
- `public/icons/icon-512-maskable.png`：Android 可裁切安全区 512×512（`purpose: maskable`）
- `public/icons/apple-touch-icon-180.png`：iOS 主屏 180×180；`index.html` 的 Apple Touch 已指向此文件

上述运行图标已换成文艺 Bot 提供的实图。母图 `pi-icon-master-1024.png` 和预览/源文件不进项目运行目录。`index.html` 的 Apple Touch 已指向 `apple-touch-icon-180.png`。

2026-11-11 重新做了一轮，解决「装出来的图标比旁边应用小一圈」和「页面内品牌图标有两个对不上的圆角框」两个问题：

- **四张安装图标统一用同一套满幅图稿**（母图 `public/icons/logo-pwa.svg`：画板铺满整张画布、圆角 22% ≈ 系统 squircle、图形占画布 80%）。`icon-192` / `icon-512` / `icon-512-maskable` / `apple-touch-icon-180` 都由它渲染，四张内容一致，系统挑哪张都一样。
- **为什么必须满幅**：Safari 的「添加到程序坞」取的是 **`maskable` 那张**（实测 `~/Applications/<名字>.app/Contents/Resources/ApplicationIcon.icns`：紫点圆心 67.5%、直径 8.0%，正好等于 maskable 的 71.8% / 10.0% × 0.8），而 macOS 会把图稿缩到画布 80% 再套圆角遮罩。图稿自己再留 10% 透明边就是缩两遍，Dock 里明显比原生应用小一圈。
- **为什么图形只到 80%**：这张同时当 `maskable` 用，Android 会按 80% 安全圆裁切；紫点最外缘离画布中心 48.6%（< 50%），圆形遮罩也切不到。图形再大就掉进不安全区了。
- **页面内标记拆成 `public/icons/mark.svg`**：透明底，只有 π 和紫点，底色/圆角/描边全交给外层容器（`.brand-mark`、`.empty-mark`、`.msg .avatar`，底色统一用 `--brand-tile: #111113`）。`public/logo.svg` 留着给浏览器标签页的 favicon 用（它自带深色圆角底）。
- **生成方式**：改 SVG 后，把 `<svg>` 标签补上 `width`/`height`（如 512）再用 `sips -s format png src.svg --out icon-512.png` 渲染；不补尺寸只会输出 64×64。QuickLook 会把透明压成白底，不能用。
- **改完图标要重新添加一次**：Safari 把生成的图标固化在 `~/Applications/<名字>.app` 里，不会自己重画；把程序坞里那个删掉、重新「添加到程序坞」才会用新图。
